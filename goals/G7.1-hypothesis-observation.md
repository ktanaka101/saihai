# G7.1 仮説に基づく観測

> 各ゴールの仮説と判定（観測の式）を読み、指標の値と件数から当たり・外れ・まだ判断できないを判定する。人が得た観測も記録し、履歴を残す。

## 意図

- 目的：ゴールごとの仮説と判定から何を観測するかを決め、値を集めて、仮説が当たったか外れたかを判定する
- 理由：今の観測（G7）は saihai 自身の固定の指標で、ゴールの仮説とつながっていない。判定の基準がゴールにあれば、観測から次の判断（続行か方向転換か）を直接導ける（G1.2、J58）
- 望ましい最終状態：`npm run observe` を開くと、ゴールごとの仮説の判定が根拠つきで並び、観測は履歴として残る。人が得た観測（利用者の声など）も同じ形で扱える

## 仮説と判定

- 仮説：仮説の判定を自動で出せば、解釈（G6.1）で使える根拠が増え、人が数値を読み解く手間が減る
- 当たりの判定：仮説を持つゴールの半分以上で、当たりか外れかを判定できる（観測：`判定できた仮説の割合 >= 0.5`）
- 外れの判定：ほとんどの仮説が判定できないままになる（観測：`判定できた仮説の割合 < 0.2`）

## 具体例

- E1 `[機械]` 観測の式を読み、指標の値と件数から、ゴールごとに当たり・外れ・どちらでもない・まだ判断できないを判定する
- E2 `[機械]` 指標は、組み込みの指標（ゴール文書・判断ログ・git・評価の結果・作業記録）と、プロジェクトが設定する観測のコマンドから集まる
- E3 `[機械]` 人が得た観測を `npm run observe -- --record 指標=値` で記録でき、件数と出どころも残せる
- E4 `[機械]` `npm run observe -- --save` で観測を履歴に残し、前回からの変化を示せる
- E5 `[機械]` 式に出てくる指標が観測できないときは「まだ観測できない」と報告し、当たりにも外れにもしない

## 不変条件

- 件数が判断に足りない指標は、当たりにも外れにもしない — 理由：偶然の揺れで判断を誤らない（J51）

## 仮置き

- 観測のコマンドは `saihai.config.json` の probes に書く — 理由：プロジェクトごとに観測の手段が違う（G7.1.E2）
- 件数のない指標（合否のような1回の値）の件数は、履歴に残した回数とする — 理由：1回の結果だけで判断しない（J51）

## 非ゴール

- 観測の解釈と次の判断（G6.1）
- 観測したデータの外部への送信

## AI 層

> ここから下は AI 向けの記録と根拠。人は根拠を確かめたいときだけ読めばよい。

### 設計

- 判定の規則
  - 当たり：当たりの判定の式がすべて成り立つ
  - 外れ：外れの判定の式のどれかが成り立つ
  - 両方が成り立つときは「矛盾」と報告する
  - 式の指標のどれかの件数が5件未満なら「まだ判断できない」（J51）
  - 式の指標が観測できないなら「まだ観測できない」
  - 判定の行に式がない（自然文だけの）ゴールは「人が判定」として、解釈（G6.1）に回す
- 組み込みの指標：v1 の10指標に加え、式で使う数値の指標（1ゴールあたりの人の判断・推奨どおりの割合・判断ログの件数・逸脱と指摘・mainの検査の失敗・判断に使える指標の割合・判定できた仮説の割合）
- 人の観測：`--record 指標=値 [--n 件数] [--note メモ] [--by 人|AI]` で `observations/log.jsonl` に記録する。同じ名前の組み込みの指標がなければ、最新の記録を指標として使う
- 履歴：`--save` で、その時点のすべての指標を `observations/log.jsonl` に1行で残す。報告では前回の値を並べる

### 前提

確かめていない前提。確かめたら「調べたこと」に移す。

- 観測のコマンドは、標準出力の最初の数値を値、2つ目の数値を件数として返せる

### 調べたこと

- G7 の調べたこと（GQM、vanity metrics と actionable metrics）を引き継ぐ
- **委任型の指示設計**（利用者の文書）：ゴールに「当たりの判定」「外れの判定」を書き、観測で仮説を確かめる

### 既知の落とし穴（プレモーテム）

「半年後にこのゴールが失敗していたら、原因は何か」

| 落とし穴 | 根拠 | 対策 |
|---|---|---|
| 判定が機械的すぎて、文脈を無視した「外れ」で方向転換してしまう | グッドハートの法則 | 判定は解釈（G6.1）の材料にとどめ、方向転換は人が決める |
| 件数が少ないまま当たりと判定する | ― | 5件未満は判定しない（不変条件） |
| 観測のコマンドが遅い・壊れていて、観測そのものが止まる | ― | コマンドの失敗は「まだ観測できない」として報告し、他の指標は出す |

### 事後検証

- 2026-10-12（判定：当たり。判定できた仮説の割合 = 0.5、10件。閾値ちょうど）
  - 注意：この事後検証の中で、判定できた仮説の割合の数え漏れ（1回目の判定に G7 の指標を入れていなかった）を直し、0.4 から 0.5 に上がって当たりになった。自分のゴールの判定を変える修正なので、判断ログに指摘として残した（D17。受信箱の事後確認に上がる）
  - なぜ当たったか：G3 の観測の手段を足し（AI の記録と観測のコマンド）、「まだ観測できない」が減った。判定できていない5件は、件数の不足（G3・G5）、人が判定（G6.1）、どちらでもない（G0）、自分自身（G7.1）
  - 測り方の限界：割合の分母に自分自身が入る。閾値ちょうどなので、仮説が1つ増えるだけで外れに近づく
  - 次にどうするか：続行。`--save` の履歴で、次の観測で下がらないかを見る。G7 の事後検証から引き継いだ「判断に使える指標の割合」の測り方の見直し（J71）は、判例や判断待ちが根拠として引いた指標を数える形を候補として残す（未着手）
