# G6 解釈と次の判断

> 観測を解釈し、次に決めるべきこと（ゴールの修正・新しいゴール・中止・続行）を、根拠の数値つきで上申する。

## 意図

- 目的：観測を解釈し、次に決めるべきこと（ゴールの修正・新しいゴール・中止・続行）を、根拠の数値つきで上申する
- 理由：観測から次の判断を導くのはボトルネック（J42）。数値を眺めるだけでは判断にならず、偶然の揺れに反応すると判断がぶれる
- 望ましい最終状態：参謀が判断を変えうる点だけを根拠と推奨つきで上げ、人は判断だけを行う

## 仮説と判定

- 仮説：根拠つきの上申に絞れば、人は少ない判断で次を決められる
- 当たりの判定：解釈からの上申が推奨どおりに決まる（観測：`推奨どおりの割合 >= 0.8`）
- 外れの判定：解釈からの上申が推奨どおりに決まらない（観測：`推奨どおりの割合 < 0.5`）

## 具体例

- E1 `[機械]` 観測の報告から、次に決めるべきことの候補（ゴールの修正・新しいゴール・中止・続行）が、判断待ちの形で書かれる
- E2 `[機械]` どの候補にも、根拠にした観測の数値と、その出どころが付いている
- E3 `[機械]` 件数が少なすぎて判断できない指標は、候補にせず「まだ判断できない」と書く
- E4 `[機械]` 過去の判例と同じ種類の判断は、その判例を引いて推奨する
- E5 `[人間]` 上申は5件まで（J45）で、どれも推奨と自明な案が付いている

## 非ゴール

- 事業や戦略レベルのゴールを AI が決めること（G0 の非ゴール）
- 観測そのもの（G7）

## AI 層

> ここから下は AI 向けの記録と根拠。人は根拠を確かめたいときだけ読めばよい。

### 設計

- 解釈は判断を伴うので、参謀（AI）が行う。手順はプロジェクトスキル `.claude/skills/interpret/SKILL.md` に書く
  1. `npm run observe` の報告を読む
  2. 指標ごとに、件数が判断に足りるかを見る。足りなければ「まだ判断できない」とする（E3）
  3. 判断を変えうる点だけを候補にする：ゴールの修正、新しいゴール、中止、続行（Lean Startup の「方向転換か、続行か」）
  4. 候補ごとに、根拠の数値と出どころ、過去の判例（あれば）、推奨と自明な案を書く
  5. 関わるゴールの文書の判断待ちに書く（5件まで）。新しいゴールが要るときは G2 の手順で草案を作る
- 決まった手順が受け持つのは、件数の不足の判定だけ。何が判断を変えうるかの見極めは参謀が行う

### 前提

確かめていない前提。確かめたら「調べたこと」に移す。

- 観測の報告（G7）が、指標ごとに件数と出どころを持っている
- 「判断に足りる件数」の目安は指標ごとに違う。最初は5件未満を「まだ判断できない」とし、判例を通じて調整する

### 調べたこと

- **Lean Startup の innovation accounting**：基準を測り、小さな実験で指標が動くかを見て、方向転換するか続けるかを決める。方向転換の兆しは、何度試しても仮説が確かめられない、指標が横ばいのまま、などとされる（入門書の要約。原典は未確認）
- **GQM**：指標は問いと目的にさかのぼって解釈する（G7 の調べたことを参照）

### 既知の落とし穴（プレモーテム）

「半年後にこのゴールが失敗していたら、原因は何か」

| 落とし穴 | 根拠 | 対策 |
|---|---|---|
| 少ない件数の揺れを傾向と読み違え、判断がぶれる | ― | 件数の不足を決まった手順で判定し、候補にしない（E3） |
| 都合のよい数値だけを根拠にする（確証バイアス） | ― | 候補ごとに根拠の数値と出どころを必ず付ける（E2）。推奨と逆の数値があれば併記する |
| 上申が多すぎて、人が読まずに承認する | アラート疲れ（G0 の既知の落とし穴） | 5件まで（J45）。判断を変えうるものだけを上げる |
| AI の解釈を人が過信する | 自動化バイアス（G2 の調べたことを参照） | 推奨には理由を付け、自明な案を必ず並べる |

### 事後検証

- 2026-10-12（判定：当たり。推奨どおりの割合 = 0.96、24件。根拠の指標は G0・G2 と共通）
  - 当たったと言えるか：言えない。根拠の指標は G2 と同じで、解釈からの上申を区別していない。しかも解釈から上申した Q34・Q35 は、どちらも J37 に基づいて参謀が推奨を採用しており、人は答えていない。G6 の仮説はまだ確かめられていない
  - 測り方の限界：同じ指標で複数の仮説を判定すると、1つの観測を二重に数える。観測の報告で、根拠の指標がすべて他の仮説の根拠に含まれる仮説には、その ID を付けるようにした（J68）
  - 次にどうするか：修正。解釈の効果は、受信箱を入り口にした G6.1 の仮説（人が判定）で確かめる。G6 の判定は独立の根拠として数えない
