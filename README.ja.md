# saihai（采配）

[English](README.md) | 日本語

人は采配を振るだけ。

ソフトウェアづくりは「ゴール設定 → 実装 → 現実からの観測 → 解釈と次の判断」のループです。実装は AI で速くなりましたが、残りの3つは人の注意力が要り、ループの速さを決めています。saihai は、この実装以外の3つを支え、人の注意力を判断にだけ使えるようにするフレームワークです。

- **ゴール設定**：一言の意図から、AI（参謀）が下調べ・仮説・理由つきの制約を添えたゴール文書の草案を作る。人は判断待ちに答えるだけ
- **実装（AI に任せる）**：実装する AI は委任指示に従い、報告条件に当たらない判断は自分で決めて判断ログに残す。main への反映は門番が行う
- **現実からの観測**：ゴールの仮説に書いた観測の式から、当たり・外れを自動で判定する
- **解釈と次の判断**：人が開くのは受信箱だけ。いま判断すべきことが5件まで並ぶ。仮説が判定されたゴールは、参謀が事後検証（AAR）して次の判断を上申する

考え方の土台は、委任型指揮（Auftragstaktik）です。人が書くのは、意図（目的・理由・望ましい最終状態）と、不変条件と、報告条件だけです。制約には理由と強さ（不変条件・推奨・仮置き）を付けるので、AI は理由に照らして逸脱を報告できます。

## いまの状態

実験段階（0.1.0）です。

- 実際に使っているのは、作者が saihai 自身を作るときだけです。ほかのプロジェクトでの実績はまだありません
- saihai 自身の仮説（1つのゴールにかかる人の判断が減り、推奨の質は保たれる）は、まだ確かめている途中です。今の判定は `node bin/saihai.mjs observe` で見られます
- ゴール文書の書式やコマンドは、予告なく変わることがあります

## 必要なもの

- Node.js 22.8 以上（依存パッケージはありません）
- git
- [Claude Code](https://code.claude.com/)（プラグイン・スキル・フックを使います）

## 使い始める

使いたいプロジェクトにだけ、プラグインを入れます。そのプロジェクトのフォルダで:

```bash
claude plugin marketplace add ktanaka101/saihai
```

```bash
claude plugin install saihai@saihai --scope local
```

`--scope local` にすると、自分の、そのプロジェクトだけで有効になります（`.claude/settings.local.json` に記録されます）。ほかのプロジェクトには影響しません。セッションの中で `/plugin install saihai@saihai` を使うときは、範囲を聞かれるので「Install for you, in this repo only」を選びます。

- `marketplace add` は、どこから入れられるかの一覧をユーザーの設定に登録するだけです。これだけではどのプロジェクトでも動きません
- チームで使うなら `--scope project`（`.claude/settings.json` に記録し、コミットして共有）、すべてのプロジェクトで使うなら `--scope user` です

あとは、そのプロジェクトで、やりたいことを一言で伝えるだけです。

> 毎月の支出の集計に手間がかかっていて、使いすぎに気づくのが月末になってしまう。早く気づけるようにしたい。ゴールにして

参謀がゴール文書の置き場（`goals/`）を作り、下調べをして草案を書き、決めてほしいことを判断待ちにします。答えるときは「受信箱」と言うだけです。判断待ちが質問の形で出てくるので、選ぶか書くかで答えます。記録は参謀が行い、人がコマンドを打つことはありません。

人がすることは次の3つだけです。

1. やりたいことを一言で伝える
2. 「受信箱」と言って、出てきた質問に答える（AI の逸脱や指摘の確認も、ここで出てきます）
3. 「振り返って」と言うと、参謀が観測して仮説を判定し、次に決めることを受信箱に上げる

もし user の範囲で入れても、saihai を使っていないプロジェクトでは、プラグインのフックは何もしません。プロジェクトに足されるのは `goals/`・`decisions/`・`observations/`・`saihai.config.json` だけで、CLAUDE.md や設定には触れません。

### main への反映を門番に任せる（任意）

`saihai.config.json` に `"guard": true` を足すと、そのプロジェクトでは AI が main に直接コミットできなくなり、門番（`saihai gate`）が検査を通したものだけを main に反映します。既定では、プロジェクトのいつものやり方を変えません。

### プラグインを使わずに入れる

プラグインを使わない場合は、saihai を clone して、プロジェクトで `init` を実行します。CLAUDE.md の saihai の節・スキル・フックもプロジェクトに入ります（既にあるファイルは上書きせず、足すだけです）。

```bash
git clone https://github.com/ktanaka101/saihai.git ~/codes/saihai
```

```bash
node ~/codes/saihai/bin/saihai.mjs init
```

## コマンド（参謀が使うもの）

人が打つ必要はありませんが、参謀は次のコマンドで記録や検査を行います。プラグインでは `saihai`、プラグインなしでは `node ~/codes/saihai/bin/saihai.mjs` で呼びます。

| コマンド | すること |
|---|---|
| `saihai inbox` | 受信箱：いま人が判断すべきこと（5件まで）と、ゴールごとの段階 |
| `saihai answer Q12 推奨` | 判断待ちへの答えを判例に移す（「自明な案」や `--text "…"` でも） |
| `saihai confirm D3 D6` | 人が見た事後確認を確認済みにする |
| `saihai new --parent G0 --slug name --title "題名" --summary "要約"` | ゴール文書の雛形を作る |
| `saihai check` | ゴール文書と判断ログを検査する |
| `saihai brief G1` | 実装する AI への委任指示（祖先のゴールの不変条件・報告条件を含む） |
| `saihai log --goal G1 --kind 判断 ...` | 判断ログに1件足す |
| `saihai observe` | 観測と仮説の判定。`--save` で履歴に残す。`--record 指標=値` で人の観測を記録する |
| `saihai aar G1` | 事後検証の材料（起きるはずだったこと・起きたこと） |
| `saihai gate` | 門番：最新の main とマージした結果を検査し、通れば main に反映して push する |

## ゴール文書

1つのゴールを1つの Markdown にします。人が読む人間層（40行まで）と、AI 向けの記録の AI 層に分かれます。

```markdown
## 意図
- 目的：…
- 理由：…
- 望ましい最終状態：…

## 仮説と判定
- 仮説：これを作れば、誰の何がどう良くなるはずか
- 当たりの判定：…（観測：`取り込み時間の中央値 <= 3`）
- 外れの判定：…（観測：`取り込みの失敗 >= 1`）

## 具体例
- E1 `[機械]` 自動で確かめる受け入れの例

## 不変条件
- 必ず守ること — 理由：なぜ（関わる ID）

## 報告条件
- 実装を止めて人に聞く条件
```

書式の詳細は [G1](goals/G1-goal-format.md) と [G1.2](goals/G1.2-format-v2.md) にあります。

## 設定（saihai.config.json）

```json
{
  "gate": {
    "checks": [{ "name": "テスト", "cmd": ["npm", "test"] }],
    "push": true
  },
  "probes": {
    "取り込み時間の中央値": { "command": "node scripts/measure.mjs", "examples": ["G1（仮説）"] }
  }
}
```

- `gate.checks`：門番の検査。既定のゴール文書の検査の後ろに足される。`push: false` にすると、リモートに push せず手元の main だけを更新する
- `probes`：観測のコマンド。標準出力の1つ目の数値が値、2つ目が件数。名前を仮説の観測の式に書くと、当たり・外れの判定に使われる

## saihai 自身

このリポジトリは saihai を saihai で作っています。ゴールは [goals/](goals/)、判断ログは [decisions/log.jsonl](decisions/log.jsonl) にあります。評価の導出（実装を見ない評価 AI と隠しシナリオ）は、今は saihai 自身にだけあります。

### 開発

- `npm test`（Node.js のテスト、行のカバレッジ80%以上）と `node bin/saihai.mjs check` で確かめます
- このリポジトリの門番（`saihai.config.json` の `gate`）は、リポジトリの外の作者の手元にある隠しシナリオの置き場を使います。そのため、ほかの人の手元では、門番の隠しシナリオと監査の検査は通りません。手元で確かめるときは、上の2つを使ってください
