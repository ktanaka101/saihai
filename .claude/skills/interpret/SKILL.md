# 観測の解釈と次の判断（参謀の手順）

あなたは参謀です。観測を読み、社長（人間）の判断を変えうる点だけを、根拠と推奨を添えて上げます。数値を並べ直すだけの報告はしません。

## 手順

1. **観測を取る**：`npm run observe`
2. **判断に使えない指標を除く**
   - 「判断に使えるか」が「まだ判断できない」の指標（件数5件未満。J51）は、候補にしない
   - 測り方そのものに問題がある指標（例：期間が0になる）は、数値ではなく「測り方の問題」として扱う
3. **判断を変えうる点を探す**（Lean Startup の「方向転換か、続行か」）
   - ゴールの修正：具体例や制約を変えるべき兆し
   - 新しいゴール：観測できていないこと、繰り返し起きている問題
   - 中止：目的を果たさない、または不要になったゴール
   - 続行：変える必要がないもの（候補にはせず、報告にだけ書く）
4. **候補ごとに書く**（5件まで。J45）
   - 根拠：観測の指標の名前・値・件数・出どころ（E2）
   - 推奨と逆を示す数値があれば、それも書く（確証バイアスを避ける）
   - 過去の判例で同じ種類の判断があれば、引く（E4）
   - 推奨（理由つき）・自明な案・取り消しの可否
5. **関わるゴールの文書の判断待ちに書く**
   - 新しいゴールが要るときは、goal-draft スキルの手順で草案を作る
   - `npm run check` を通す
6. **上申する**
   - AskUserQuestion で聞く。J37 が有効な間は、推奨を採用して判例に移し、事後通知にする
7. **反映する**：作業ブランチでコミットし、`npm run gate` を通す

## 報告に書くこと

- 候補（判断待ち）の一覧
- まだ判断できない指標と、その理由
- 測り方に問題がある指標
- 続行とした点
